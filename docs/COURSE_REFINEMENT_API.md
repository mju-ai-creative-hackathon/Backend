# 진행 중인 코스의 남은 일정 수정

사용자가 선택한 코스에서 **마지막으로 완료한 장소**를 선택하고, 이후에 원하는 일정을 프롬프트로 입력합니다. 완료한 장소와 촬영 미션은 보존하고 이후 일정만 새로 구성합니다.

## 요청

`POST /api/courses/{id}/remaining-refinements`

`Authorization: Bearer <accessToken>`이 필요합니다. 기본 코스 또는 본인이 생성한 AI 코스에만 요청할 수 있습니다.

```json
{
  "completedThroughStopSeq": 2,
  "prompt": "비가 와서 이후에는 실내 위주로 바꿔줘. 저녁에는 일식을 먹고 싶어.",
  "lat": 37.5796,
  "lng": 126.9770
}
```

| 필드 | 설명 |
| --- | --- |
| `completedThroughStopSeq` | 마지막으로 완료한 장소의 `seq`. 해당 장소까지 순서대로 모두 완료했다는 뜻입니다. 아직 방문 전이면 `0`을 전송합니다. |
| `prompt` | 이후 일정에 대한 수정 요청. 공백을 제외한 내용이 필요하며 최대 500자입니다. |
| `lat`, `lng` | 선택 입력인 현재 위치. 제공하려면 두 값을 함께 전송합니다. |

완료 지점은 상세 응답의 `stops[].seq`로 선택합니다. 예를 들어 `seq`가 `1, 2, 3, 4`인 코스에서 `2`를 보내면 장소 1~2는 유지하고 이후 일정을 수정합니다. 완료 장소를 임의로 여러 개 체크하는 형식은 지원하지 않습니다. 모든 장소를 완료했거나 존재하지 않는 완료 지점을 보낸 경우에는 수정할 남은 일정이 없으므로 `400`입니다.

현재 위치를 제공하면 이후 일정 생성의 기준 위치로 사용합니다. 위치를 생략하고 완료 장소가 있으면 마지막 완료 장소를 기준으로 삼습니다.

## 응답과 보존 범위

성공하면 `200`과 기존 코스 상세 조회와 같은 `CourseDetail`을 반환합니다. 원본 코스를 덮어쓰지 않고 **요청자 소유의 새 AI 코스**를 생성하므로 응답의 `id`는 원본과 다릅니다.

- `stops`: 완료한 기존 장소들과 새로 구성한 이후 장소들을 방문 순서대로 반환합니다.
- 완료한 장소의 이름·설명·주소·위치·사진·방문 일차·시간·체류 시간은 유지합니다.
- 완료한 장소의 촬영 미션 내용은 유지하고, 이후 장소에는 수정된 일정에 맞는 미션을 연결합니다.
- 완료한 장소는 남은 일정에 중복해서 추가하지 않습니다.
- 전체 코스는 기존 AI 코스와 같이 최대 8개 장소입니다. 완료 구간을 보존한 뒤 남는 자리만 새 장소로 채웁니다.
- 새 장소의 예정 시각은 마지막 완료 장소의 체류·이동 이후로 조정하며, 자정을 넘으면 다음 일차로 이어집니다. 이는 실제 도착을 보장하는 시각이 아닌 계획입니다.
- `totalMinutes`는 완료 구간을 포함한 전체 일정의 예상 시간입니다. 완료 구간 비용을 별도로 알 수 없으면 전체 `estimatedCost`는 `null`입니다.
- 변경되지 않은 원본 코스도 기존 ID로 계속 조회할 수 있습니다.

이후 일정의 시작 시간은 마지막 완료 장소의 예정 체류 종료와 예상 이동 시간을 고려해 조정합니다. 자정을 넘으면 다음 여행 일차로 넘어갑니다. `totalMinutes`는 완료 구간을 포함한 전체 계획 기준의 예상 시간입니다. 완료 구간의 비용을 따로 알 수 없는 경우 잘못된 합계를 표시하지 않도록 `estimatedCost`는 `null`입니다.

새 코스의 촬영 미션에는 새로운 ID가 부여됩니다. 원본 코스에 연결된 숏폼 프로젝트와 업로드 파일을 자동으로 새 코스에 옮기지 않습니다. 새로운 촬영 미션을 사용할 때는 새 응답의 코스·미션 ID를 사용하고, 이미 수집한 소스와 원본 미션의 연결은 별도로 유지해야 합니다.

진행 중인 일기장의 `courseId`와 `courseTitle`은 일정 시작 당시의 스냅샷으로 유지합니다. 이 API는 현재 화면에서 사용할 계획을 새로 만들며 일기장을 다시 시작하지 않습니다. 앱은 반환된 코스 ID를 현재 계획으로 보관하되, 위치·걸음수 기록은 기존 일기장 ID로 계속 수집하고 종료해야 합니다.

## 프론트 연결 순서

1. 현재 코스 상세를 조회하고 장소를 순서대로 보여줍니다.
2. 사용자가 마지막으로 완료한 장소에서 **여기까지 완료**를 선택합니다. 아직 시작 전이라면 **완료한 장소 없음**을 선택합니다.
3. 남은 일정의 수정 요청을 입력하고 이 API를 호출합니다. 생성 중에는 중복 제출을 막고 로딩 상태를 표시합니다.
4. 성공하면 원본 대신 반환된 코스를 현재 계획으로 표시합니다. 완료 지점은 요청 때 선택한 값을 유지하고, 이후 장소부터 안내합니다.
5. 추가 수정 시에는 가장 최근에 반환된 코스 ID와 그 코스의 완료 지점으로 다시 요청합니다.

응답의 `legs`는 완료한 장소를 포함한 전체 코스의 인접 구간입니다. 진행 중 안내는 마지막 완료 장소 다음의 `seq`부터 시작해야 합니다. `startLeg`는 전체 코스의 원래 출발 구간이므로 이미 방문한 1번 장소로 되돌아가는 안내에 사용하지 않습니다.

완료 여부는 요청자가 선택한 진행 상황입니다. GPS 방문 인증이나 촬영 미션 수행 인증으로 취급하지 않습니다.

## 오류

| HTTP 상태 | 상황 |
| --- | --- |
| `400` | 프롬프트·완료 지점·좌표가 올바르지 않거나 모든 장소가 이미 완료됨 |
| `401` | 로그인 토큰이 없거나 유효하지 않음 |
| `404` | 코스가 없거나 다른 사용자의 비공개 AI 코스임 |
| `429` | 기존 AI 코스 생성·수정 요청 제한 초과 |
| `502` | AI 결과에서 사용할 수 있는 남은 장소를 확보하지 못함 |
| `503` | AI 생성 서비스 사용 불가 |

실패하면 원본 코스는 유지됩니다. AI와 장소 조회가 필요하므로 즉시 응답하는 API는 아닙니다.
