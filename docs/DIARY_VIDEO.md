# 일상 기록형 편집 계획 및 로컬 영상 제작

참고 YAML의 컷 역할·길이·선택 슬롯 개념을 서울 하루 일정에 맞게 일반화한 임시 구현입니다.
시험 기간, DAY 1~6, 사용자의 감정이나 실제로 하지 않은 활동을 자동으로 만들어 넣지 않습니다.
추가 유료 LLM이나 영상 생성 API를 호출하지 않고 원본 메타데이터와 편집 규칙으로 계획을 만듭니다.

## 제작 흐름

1. 기존 `/api/shortforms` 프로젝트에 사진·동영상 5~20개를 업로드합니다.
2. 원하는 소스 순서·스타일·무드와 목표 길이를 정합니다.
3. 편집 계획 API로 컷별 원본 ID, 구간, 배치 시각, 움직임, 화면 문구, 음향 지침을 확인합니다.
4. 외부 AI 어댑터에 계획·프롬프트를 전달하거나 실험용 로컬 FFmpeg 렌더러로 제작합니다.
5. 기존 제작 작업 상태 API로 완료를 확인하고 인증된 결과 영상 API를 호출합니다.

기존 스타일 코드는 유지합니다. `VLOG`를 선택하면 일상 기록형 브이로그를 실험할 수 있습니다.
현재 로컬 계획의 컷 배치 규칙은 공통 일상 기록형입니다. 스타일·무드 코드는 외부 전달 프롬프트에
포함되며, 로컬에서 각 스타일의 고유한 색보정이나 무드별 음악을 자동 재현하는 기능은 아닙니다.
이미지는 편집 과정에서 제한된 확대·이동을 적용하고 동영상은 실제 길이 내에서 구간을 선택합니다.
소스가 부족하면 목표 길이를 채우려고 영상을 만들어 늘리지 않고 경고와 짧은 계획을 반환합니다.

## 편집 계획 미리보기

```http
POST /api/shortforms/PROJECT_ID/edit-plan
Authorization: Bearer ACCESS_TOKEN
Content-Type: application/json

{
  "style": "VLOG",
  "mood": "CALM",
  "musicId": null,
  "renderProvider": "local",
  "targetDurationSec": 35,
  "assetIds": ["UUID_1", "UUID_2", "UUID_3", "UUID_4", "UUID_5"]
}
```

소스는 해당 사용자의 프로젝트에 속해야 합니다. 목표 길이는 기본 35초, 허용 범위는 15~90초입니다.
계획은 `templateId`, `version`, 출력 해상도·FPS·길이, `cuts`, `audio`, `prompt`, `warnings`를 포함합니다.
컷에는 원본 ID, 역할, 타임라인 시작, 원본 시작, 사용 길이, 편집 움직임, 화면 문구, 프레임 배치 방식이 있습니다.

계획은 실제 영상 장면을 이해해서 우수한 순간을 찾는 시각 모델의 분석 결과가 아닙니다.
동영상의 실제 길이와 해상도·오디오 여부를 확인하고 선택 순서와 규칙으로 구간을 배정합니다.
기존 일정·미션 촬영 가이드는 의도에 관한 참고 정보이며 해당 활동을 실제로 수행했다는 증거로 사용하지 않습니다.

## 로컬 FFmpeg 모드

FFmpeg와 FFprobe가 설치된 서버에서만 사용합니다. 제작 요청마다 `renderProvider: "local"`을 지정하면
서버 기본 공급자가 `remote`이고 외부 AI가 미설정이어도 로컬 제작을 선택할 수 있습니다.
`GET /api/shortforms/options`의 `renderProviders` 배열에서 현재 사용 가능한 공급자를 확인합니다.
이미 등록한 작업은 공급자를 DB에 기록하므로 이후 서버 기본값이 바뀌어도 같은 공급자로 처리됩니다.

바이너리 경로와 서버 기본값을 지정할 때는 다음 환경변수를 앱 실행 환경에 전달합니다.

```text
SHORTFORM_RENDER_PROVIDER=remote
SHORTFORM_FFMPEG_PATH=ffmpeg
SHORTFORM_FFPROBE_PATH=ffprobe
```

기존 제작 요청 `/api/shortforms/{projectId}/renders`와 상태 조회 흐름을 사용합니다.
요청 본문은 미리보기와 동일하며 `renderProvider: "local"`을 포함하고 기존 UUID `Idempotency-Key` 헤더를 보냅니다.
같은 멱등성 키의 목표 길이나 공급자를 바꾸면 409입니다. 공급자를 생략하면 서버 기본값을 사용합니다.
완료된 로컬 영상과 썸네일은 다음 경로에서 소유자의 Bearer 인증으로 조회합니다.

```http
GET /api/shortforms/PROJECT_ID/renders/RENDER_ID/video
GET /api/shortforms/PROJECT_ID/renders/RENDER_ID/thumbnail
```

사진·영상의 세로 출력 규격을 맞추고 사진에는 제한된 움직임을 넣습니다.
음향은 원본 현장음 보존·음량 보정을 기준으로 하며 외부 음악 파일은 자동으로 구하거나 합성하지 않습니다.
로컬 모드에서 지원하지 않는 음악 ID를 지정하면 오류로 처리합니다.
화면 문구를 렌더링하려면 사용할 글꼴 파일이 서버에 있어야 합니다.
비공개 원본·결과 파일은 로컬 저장소와 운영 볼륨에 보관하며 다중 서버에는 공유 저장소가 필요합니다.

## 기존 외부 AI 모드

기본 렌더링 공급자는 `remote`입니다. 기존 `SHORTFORM_AI_ENABLED`, `SHORTFORM_AI_BASE_URL`,
`SHORTFORM_AI_API_KEY` 설정을 유지합니다. `renderProvider: "remote"`를 선택했는데 외부 서버가 준비되지 않았으면
기존처럼 제작 불가를 반환합니다. 이 상태에서도 준비된 `local` 공급자를 명시적으로 선택할 수 있습니다.

```text
SHORTFORM_RENDER_PROVIDER=remote
SHORTFORM_ENHANCED_EDITING_ENABLED=true
```

향상된 편집 정보 전달은 명시적으로 켜는 기능입니다. 외부 AI 서버가 새 계획·프롬프트 필드를
처리하도록 합의한 뒤 활성화합니다. 기본 설정에서는 기존 외부 서버의 계약을 유지합니다.
내보낸 프롬프트 자체는 추가 LLM 호출이나 결과 품질을 보장하지 않습니다.

## 버전별 스타일 설정

서버 소유의 `src/main/resources/shortform/daily-diary-v1.yaml`에 템플릿 ID·버전, 출력 규격,
사진 최대 길이·도입/마무리 길이와 기본 화면·음향 규칙이 있습니다. 이 파일을 수정하고 재빌드해서
같은 소스에 적용할 편집 설정을 바꿀 수 있습니다. 지원하는 설정 범위는 `DiaryStylePreset`의 검증을 따릅니다.
실제 사용자의 YAML 업로드나 실행 명령·필터 문자열 입력은 받지 않습니다. 근거 없는 날짜·감정·행동을
생성하지 않는 제한은 사용자 설정으로 해제하지 않습니다.

## 현재 한계와 평가

- 원본의 장면 의미·흐림·흔들림·얼굴 위치를 자동 평가하지 않습니다.
- 음악 박자 분석, TTS 내레이션 생성, 음성 인식 자막은 포함하지 않습니다.
- 생성형 카메라 움직임이나 인물·장소 변형은 하지 않습니다.
- 목표 길이, 자막 가독성, 구간 선택을 개선하기 위한 규칙이며 실제 사용자 영상으로 품질 향상을 입증한 상태는 아닙니다.
- 같은 원본으로 기존 결과와 비교해 장면 선택, 이야기 흐름, 음량, 글자 가독성, 처리 시간과 실패율을 평가해야 합니다.

Java 21과 Docker가 켜진 환경에서 `./gradlew build`로 기존 PostgreSQL 통합 테스트와 편집 계획 테스트를 실행합니다.
`LocalDiaryIntegrationTests`는 FFmpeg·FFprobe가 설치된 환경에서 사진 업로드부터 실제 MP4·썸네일
생성, 출력 규격 검사, 소유권 검증까지 실행합니다. 두 도구가 없으면 해당 테스트는 명시적으로 건너뜁니다.
워커의 로컬 렌더링 임대는 600초이며 기존 원격 제작의 임대는 120초입니다.
