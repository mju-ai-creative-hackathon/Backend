# 나의 기록 · 일정 일기장 API

모든 API는 `Authorization: Bearer <accessToken>`이 필요합니다. 기록은 본인에게만 보이며 다른 사용자의 기록 ID로 접근하면 `404`를 반환합니다.

앱에서 위치 권한과 걸음수 권한을 받은 뒤 센서 정보를 수집합니다. 백엔드는 단말의 GPS나 걸음수 센서에 직접 접근하지 않습니다. 시작 시 기록을 만들고, 종료 시 앱이 모아 둔 이동 경로와 **이번 일정 동안의 걸음수**를 한 번에 전송합니다. 자정이 지나도 단말의 하루 누적 걸음수 전체를 보내지 않도록 일정 시작값과의 차이를 계산해야 합니다.

## 1. 일정 시작

`POST /api/diaries`

```json
{
  "courseId": 1,
  "title": "친구와 함께한 서울 산책"
}
```

- `courseId`: 선택한 코스 ID.
- `title`: 선택 입력, 최대 100자. 생략하면 코스 제목을 사용합니다.
- 응답: `201`, 생성한 기록의 상세 정보. `id`와 서버가 반환한 `startedAt`을 단말에 보관합니다.
- 사용자마다 진행 중인 일정은 하나입니다. 이미 시작한 일정이 있으면 `409`입니다.
- 코스 제목은 시작할 때 복사해 두므로 이후 원본 코스가 변경되어도 당시의 제목이 유지됩니다.

`GET /api/diaries/active`로 진행 중인 기록을 다시 조회할 수 있습니다. 있으면 `200`, 없으면 `204`입니다. 앱 재실행 시 이 API와 단말에 저장해 둔 수집 정보를 이용해 이어서 기록할 수 있습니다.

## 2. 일정 종료 · 수집 정보 업로드

`POST /api/diaries/{id}/complete`

```json
{
  "endedAt": "2026-11-06T09:00:00Z",
  "steps": 8234,
  "points": [
    {
      "latitude": 37.5712,
      "longitude": 126.9768,
      "recordedAt": "2026-11-06T05:01:00Z"
    },
    {
      "latitude": 37.5720,
      "longitude": 126.9790,
      "recordedAt": "2026-11-06T05:02:00Z"
    }
  ]
}
```

- 시각은 UTC 오프셋이 있는 ISO 8601 값입니다. 위 예시는 `startedAt`이 `05:01:00Z`보다 이른 일정이라는 가정입니다.
- `steps`: 일정 구간의 총 걸음수, 0 이상 정수.
- `endedAt`: 시작 시각 이상의 종료 시각. 단말 시계 오차를 고려해 서버 현재 시각보다 최대 30초 앞선 값까지 허용합니다.
- `points`: 최대 10,000개. 위도 `-90~90`, 경도 `-180~180`이며 위치별 수집 시각이 시작~종료 구간 안에서 시간순으로 정렬되어 있어야 합니다. 같은 수집 시각은 허용합니다.
- 위치 권한이 없거나 수집하지 못했다면 빈 배열 `[]`을 보낼 수 있습니다. 없는 경로를 임의로 생성하지 않습니다.
- 성공하면 `200`, `status`가 `COMPLETED`인 상세 정보를 반환합니다. 모든 위치 정보와 걸음수를 하나의 트랜잭션으로 저장합니다.
- 이미 종료한 기록에 다시 종료 요청하면 `409`입니다. 네트워크 오류로 성공 여부가 불확실하면 상세 조회로 상태를 확인하세요.
- 성공 응답을 받기 전에는 단말에 보관한 수집 데이터를 지우지 않는 것을 권장합니다. 종료 전에는 위치/걸음수 데이터가 서버에 업로드되어 있지 않으므로 단말 데이터를 잃으면 백엔드에서 복구할 수 없습니다.

## 3. 마이페이지 나의 기록

`GET /api/diaries?page=0&size=10`

완료된 본인 기록만 최신순으로 조회합니다. 진행 중인 기록은 `/active`에서 조회합니다. 기본값은 `page=0`, `size=10`이며 `page`는 0 이상, `size`는 1~50이어야 합니다. 응답은 `content`, `page`, `size`, `totalElements`, `hasNext`를 포함하는 페이지 형식입니다.

목록에서는 다음 정보를 사용합니다.

| 필드 | 화면에서 사용할 정보 |
| --- | --- |
| `id` | 상세 조회에 사용할 기록 ID |
| `recordDate` | 일정 시작일, `Asia/Seoul` 기준 `YYYY-MM-DD` |
| `courseTitle` | 일정 시작 당시 코스 제목 |
| `title` | 사용자가 정한 일기 제목 |
| `steps` | 해당 일정의 총 걸음수 |
| `footprintSvg` | 실제 이동 경로를 축소한 SVG 그림 |
| `startedAt`, `endedAt` | 일정 시작·종료 시각 |

`GET /api/diaries/{id}`는 상세 정보와 `memo`, 수집한 `points`를 반환합니다. 원본 좌표를 이용해 앱에서 지도 위에 경로를 표시할 수도 있습니다.

`footprintSvg`는 지도 배경 없이 이동 궤적을 보여 주는 `320 × 200` 비율의 그림입니다. 초록 점은 출발, 빨간 점은 도착입니다. 경로가 없으면 빈 SVG, 한 점이면 해당 점만 반환합니다. 미리보기는 최대 1,000점으로 축소하며 저장한 원본 좌표는 유지합니다. 앱의 SVG 렌더러로 표시하면 됩니다. SVG 안에 외부 이미지나 스크립트는 없습니다.

## 4. 제목 · 메모 저장

`PATCH /api/diaries/{id}`

```json
{
  "title": "한강에서 마무리한 하루",
  "memo": "걷는 시간이 많았지만 노을이 정말 좋았다. 다음에는 카페도 들르기."
}
```

완료된 기록의 제목과 메모를 수정합니다. 두 필드를 모두 전송해야 합니다. 제목은 공백을 제외한 내용이 있어야 하며 최대 100자, 메모는 최대 5,000자입니다. 메모를 지우려면 빈 문자열을 전송합니다. 응답은 `200` 상세 정보입니다. 진행 중인 기록 수정은 `409`입니다.

## 5. 삭제 · 기록 취소

`DELETE /api/diaries/{id}` → `204`

본인의 완료 기록 또는 진행 중인 기록을 삭제합니다. 진행 중인 기록을 삭제하면 일정 취소로 처리할 수 있습니다. 연결된 이동 경로도 함께 삭제됩니다.

## 프론트 연결 순서

1. 코스 선택 → 시작 API → `id`, `startedAt` 보관.
2. 위치·걸음수 수집을 단말에 저장. 앱이 백그라운드로 이동하거나 재실행될 때의 권한·저장은 앱에서 처리.
3. 종료 버튼 → 센서 수집 종료 → 종료 시각·일정 걸음수·수집 위치를 종료 API로 전송.
4. 성공 후 마이페이지 목록 갱신 → 상세 화면에서 제목·메모 편집.

로그인하지 않았거나 토큰이 유효하지 않으면 `401`, 잘못된 수집 데이터는 `400`, 없는 기록 또는 다른 사람의 기록은 `404`, 일정 상태가 맞지 않으면 `409`를 반환합니다. 오류 응답은 기존 공통 형식인 `code`, `message`, `errors`, `timestamp`를 사용합니다.
